AR Studio

Compile targets, place content, preview, export. Everything runs in this tab — nothing is uploaded.
Settings persist in this browser. Files do not — re-pick them after a reload.
Step 1

Image targets

Add one or more. Flat, matte and feature-rich tracks best — many distinct corners, not large flat areas. ~1000 px on the long edge is plenty. Several targets compile into a single .mind, each addressed by its index.

Step 2

Content

What appears on target #0. The target is one unit wide, so scale 1 is roughly target-sized and 0 0 0 is its centre.

The plane is your target at the scale the tracker uses: one unit wide, with its height from the image aspect. 0 0 0 is the target's centre and +Z comes towards the viewer, so these are the same numbers the preview and the bundle use — place it here and it lands there. Drag to orbit.

Tracking options

filterMinCF lower = smoother but laggier · filterBeta higher = more responsive. Library defaults are 0.001 and 1000. warmupTolerance frames before a target counts as found, missTolerance before it counts as lost.

Step 3

Preview & export

The preview runs the real tracker. Export gives you a folder that works as-is.

MediaPipe returns 52 ARKit blendshapes every
  frame — jawOpen, mouthPucker,
  mouthFunnel and the rest. This maps them onto a .glb's
  morph targets, so the model mouths what you mouth. The same shape is spelled
  mouthSmileLeft, mouthSmile_L or
  blendShape1.mouthSmile_L depending on who exported it; all three are matched.
  Pick a .glb above and it is checked immediately — target count, how many
  match, and whether A-Frame can decode it at all.
  Baked facial animation is dropped while this is on — an animation clip and live blendshapes
  write to the same influences and the clip wins. Export plain glTF/GLB: KTX2-compressed or
  meshopt-packed models need decoder paths that A-Frame leaves empty by default — the generated
  pages now set them, so those load too. Draco needs nothing: A-Frame ships a decoder path for it.

  

  

    Tracking options
    

    

    

    

    

    

    
    
    
    
    
    

    
These are One-Euro filter settings:
  cutoff = filterMinCF + filterBeta × speed.
  filterMinCF governs how much it smooths when you are still — lower is steadier but laggier.
  filterBeta governs how quickly smoothing is abandoned as you move — higher follows fast
  motion but lets noise through when you are still, because camera noise has a non-zero speed too.
  If the mask shakes while you hold still, lower filterBeta. If it lags when you turn your head,
  raise it. mind-ar ships 0.001 and 1000; 1000 is very aggressive, so the default here is
  60. Reasoned from how the filter is defined, not measured — a fake camera feed is too
  stable to reproduce real sensor jitter, so this one needs your eyes on a real phone.

  

  

    
    
    
    
  

  
Anchors are MediaPipe FaceMesh indices,
  0–467; the presets are the commonly used ones. The occluder is a
  head-shaped mask hiding geometry behind the face — without it, glasses arms and hats render
  straight through the head.

Reference

  
Getting a model to talk

  
Everything needed to pick a model, or work out why one does nothing. The same
  notes, in full, are in the
  FAQ.


  

    Quickest path
    
    
      
  1. Press Use test head above. It loads a model bundled in this repo with all 51
      drivable ARKit shapes, and sets type, scale, anchor and the checkbox for you.
    2. 
      
  2. Press Start preview and allow the camera.
    3. 
    

    
The preview corner shows morphs 51/51 matched. If that reads 51/51
    and nothing moves, the problem is the setup, not the model — which is why the test head ships
    here.

  


  

    What a model needs — four separate things
    
    
      
  1. Morph targets (blend shapes / shape keys) at all.
    2. 
      
  2. Named with the ARKit set — jawOpen,
      mouthPucker and so on.
    3. 
      
  3. Plain glTF — no KTX2, meshopt or Draco. A-Frame installs none of those loaders.
    4. 
      
  4. Light enough for a phone — under ~300k triangles and ~8 MB of textures.
    5. 
    

    
A model can satisfy three and still do nothing. Pick a .glb above
    and all four are checked from the file alone — no camera, no upload.

    
A skeleton rig is not a blendshape rig. Mixamo characters animate a body through
    joints and have zero facial morph targets. Image-to-3D output (Meshy, Tripo) is one dense static
    mesh — no skin, no animation, no morphs. Neither will ever talk.

  


  

    Scale — the reason a correct model looks like nothing
    
mind-ar's face space is roughly centimetres. The anchor sits about 100 units from the
    camera and carries its own scale from the detected face, so the numbers are nothing like
    A-Frame's usual metres. Measured with the bundled test head:

    

      
1~21% of frame height — floats on the face

      
3~62% — covers the head. Start here.

      
8~160% — off screen

    

    
The Scale default of 0.1 suits the box, plane and text
    primitives. At 0.1 a head is about 12 px — present,
    correctly placed, invisible.

    
Full-body avatars (Ready Player Me) have their origin at the feet, so on a face anchor
    you see the shoes. Use a head-only model for a mask.

    
Chin showing below the mask? Anchor 168 sits between the eyes, so a head centred
    on it rides high and your real jaw stays visible underneath. Nudge Pos Y negative —
    -0.3 is usually enough, and is what the test-head button sets. Raising
    Scale also works but makes the head cartoonishly large before it covers. Position is in
    anchor units, so it is sensitive: -4 throws the mask off the bottom of
    the screen.

  


  

    It will not load, or will not move
    
"A-Frame cannot decode this file" — KTX2, meshopt or Draco. Re-save as plain glTF,
    which leaves geometry, morph targets and textures untouched:

    
npm install @gltf-transform/cli
npx gltf-transform cp packed.glb plain.glb

    
"none match the ARKit names" — the same shape is spelled
    mouthSmileLeft, mouthSmile_L,
    mouthSmile.L or blendShape1.mouthSmile_L
    depending on the exporter. All four are matched automatically. If it still reports 0 the names
    are genuinely something else — rename the shape keys in Blender and re-export.

    
Too heavy —
    npx gltf-transform optimize big.glb small.glb --texture-size 1024

    
Matched, but still still — is Talk with the face ticked? And does the model carry
    a baked facial animation? A clip writes the same influences every frame and wins; the generated
    page drops animation-mixer automatically when morphs are driven.

  


  

    Where to get a model
    
Bundled and verified: the test head above — 51/51 ARKit, 12k triangles, ~1 MB,
    MIT licensed.

    
Ready Player Me — append
    ?morphTargets=ARKit to the avatar's
    .glb URL. Tested at 51/51. Never add
    ?lod=2: it keeps a quarter of the triangles and the morph targets come
    back empty.

    
You do not need all 52. Whatever subset exists is driven, and the preview names what is
    missing. A convincing mouth needs about ten:

    
jawOpen  mouthClose  mouthFunnel  mouthPucker
mouthSmileLeft  mouthSmileRight  mouthStretchLeft
mouthStretchRight  mouthShrugUpper  mouthRollLower

    
Ten hand-sculpted shape keys on a character you already have is free and about a day's work.
    Eyes and brows start working the moment the names exist, with no code change.

  


  

    Does this need a microphone?
    
No. A virtual mask does not block the camera — MediaPipe still sees the real mouth in
    the video, so the movement comes from face tracking. Audio is a separate matter, needed only for
    a different voice (pitch shift or conversion), lip-syncing to speech the wearer is not actually
    performing, or amplitude-reactive effects.

  









  
Step 1

  
Load a head

  
Takes any .glb and gives it ARKit morph targets, so a
  model that cannot talk can. Everything happens in this tab — the model is never uploaded.

  

    
    
  

  






  
Step 2

  
Paint the jaw

  
Paint everything that should swing with the jaw — the chin and the lower
  lip — fading to nothing at the jawline and the mouth corners. Leave the upper lip unpainted:
  that separation is the entire reason this cannot be done automatically. If both lips move
  together the mouth never opens.

  

  

    
    
    
    
  

  

    

      

  

  
Jaw is everything that swings when the mouth opens. Lips is the ring
  of geometry right around the mouth opening, upper and lower together — that band is what pulls,
  purses and smiles. Paint both; they overlap on the lower lip and that is correct.

  

    

    

  

  
Drag to paint, shift-drag to erase. Untick Paint to rotate the model.

  






  
Step 3

  
Generate and export

  
The shape is a rigid rotation of the painted region about a hinge — measured at
  97.5% of an authored jawOpen on a real ARKit head. The hinge is
  derived from the painted region; override it if the jaw swings from the wrong place.

  

    

    

    

    

  

  

    

  

  

    
    
    
  

  

  

    

    

    

      

  

  

  
Lip movement % scales the nine lip shapes together. They are calibrated so
  that, driven at the same time as an open jaw, they move the lip ring about half as far as
  jawOpen does — measured, because at the original strength the jaw moved
  the mouth five times more than the mouth shapes did and a purse or a smile was invisible
  underneath it. Raise this if your character needs a broader mouth, lower it if expressions look
  rubbery.

  
The ten are jawOpen mouthClose mouthFunnel mouthPucker
  mouthSmileLeft mouthSmileRight mouthStretchLeft mouthStretchRight mouthShrugUpper
  mouthRollLower — enough to talk. Then load the exported file in Face tracking: the
  checker reports what matched and Talk with the face drives it. Export re-encodes textures
  and can grow the file; run it through
  gltf-transform optimize before putting it on a phone.









  
Step 1

  
Where it points

  
The code a visitor scans to reach the experience. Keep the URL short — measured:
  https://ar.verticecriativo.pt is 33×33 modules at level H,
  and the same URL with campaign parameters is 49×49. Half again as dense, for nothing a
  visitor can see, and it is density that makes a code fail off a glossy screen.

  

    

      

    

    

    

    

    

    

    

    

  

  

    Colour
    
    
    
    
    
    
    
    
  

  

    
    
    
    
  

  
Upload any mark to make codes for the other things you own
  — it is embedded in the SVG, so the file stays self-contained. Centre art forces level H and
  covers about 22%, within what H recovers. Rounded finders keep the 1:1:3:1:1 ratio a reader
  measures, which is why they work in practice — but they are a deviation from the spec. With
  either, scan the real output at the real distance before you rely on it. Dark-on-light scans most
  reliably; inverting works on most readers, not all. Every swatch here is dark enough to clear
  4:1 on white — the measured contrast is shown below, and a pale colour is where consumer QR tools
  quietly break codes.

  

  

  

    
    
  

  
SVG is vector — it scales to any slide or print size
  without softening. PNG is for tools that will not take SVG.
